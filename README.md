# Currency & AI Trading Bot — showcase

Telegram-бот для трейдеров и держателей крипты/валюты: курсы, технические
сигналы (RSI/MACD/EMA), AI-дайджест рынка и объяснение сигналов через
LLM-агента, и опциональная автоторговля на бирже (Binance/Bybit) для
платного тира. Показывает связку из двух Spring Boot-процессов — сам бот и
отдельный самописный MCP-сервер, который отдаёт AI-агенту стандартизированные
инструменты вместо того, чтобы жёстко прошивать вызовы внешних API в промпты.

> **Автоторговля тестировалась только в бумажном/sandbox-режиме бирж —
> реальными деньгами не торговала ни разу.** Архитектура исполнения сделок
> ниже показана как есть — она не зависит от того, paper это или боевой
> режим, разница только в ключах биржи.

## Архитектурные решения

### Отдельный MCP-сервер вместо инструментов внутри промпта

AI-агент (в проде — Timeweb Cloud AI Agent, OpenAI-совместимый эндпоинт)
получает доступ к живым данным не через жёстко вшитый в промпт контекст, а
через собственный MCP-сервер (`mcp-server/`, отдельный Spring Boot-процесс,
отдельный порт). Три инструмента:

- `search_news` — поиск свежих крипто-новостей по RSS (CoinDesk/CoinTelegraph/Decrypt)
- `get_fear_greed_index`, `get_live_price` — публичные рыночные данные, без контекста пользователя
- `get_user_portfolio` — единственный инструмент, которому нужны данные конкретного пользователя

Агент сам решает, вызывать инструмент или нет — в отличие от дайджеста
внутри самого бота, где выбор данных детерминированный (оператору важно,
чтобы утренний дайджест не зависел от того, решит ли модель в этот раз
дёрнуть RSS или нет).

### `get_user_portfolio`: без общей БД между двумя сервисами

Показательное решение: `mcp-server` не имеет доступа к базе бота напрямую.
Вместо этого бот поднимает `GET /internal/portfolio/{chatId}` —
read-only эндпоинт, защищённый общим секретом в заголовке (`X-Internal-Token`),
`mcp-server` дёргает его по HTTP и форматирует ответ для агента. Осознанный
выбор: бот остаётся единственным владельцем своих данных, `mcp-server` —
просто ещё один HTTP-клиент, а не второй процесс с прямым доступом к Postgres.
Меньше связанности между сервисами, каждый можно перезапускать/деплоить
независимо.

### Автоторговля — намеренно без AI в контуре исполнения

AI-агенту сознательно не дан доступ к исполнению сделок через MCP. Модель
участвует в анализе и объяснении сигналов, но фактическое выставление
ордера на бирже — только детерминированный код (`TradeHandler`/`TradeScheduler`,
без единого вызова LLM). Решение принято прямо: непредсказуемость языковой
модели — риск, который не оправдан, когда на кону реальные (пусть здесь и
бумажные) сделки. Разделение "AI решает/объясняет" и "код исполняет" —
воспроизводимый паттерн, не специфичный для трейдинга.

### Баг: гонка состояний ломала ввод секрета биржи

Реальный кейс из истории проекта: у шагов ввода API-ключа/секрета биржи
(`TRADE_AWAIT_API_KEY`/`TRADE_AWAIT_SECRET`) не было отмены, а устаревшая
reply-кнопка "◀️ Назад" оставалась видимой поверх экрана. Нажатие на неё
приходило боту обычным текстом — и **сохранялось как будто это и есть
секретный ключ биржи**. Не косметика — порча учётных данных пользователя.

Исправлено через `util/NavigationUtil.cancelToIdle` — единая точка отмены
для любого шага, ожидающего свободный текст (конвертер, admin-грант,
настройка биржи, вопрос AI по портфелю). Два независимых входа (inline-кнопка
"❌ Отмена" и перехват устаревшего "Назад" в диспетчере апдейтов) сходятся в
одной точке вместо точечных патчей в каждом хендлере. Тест на этот сценарий
(`NavigationRaceConditionTest`) — единственный тест в проекте, специально
написан для витрины: показывает баг напрямую через `TradeHandler`, затем
подтверждает, что условие диспетчера его предотвращает.

## Стек

- Java 17, Spring Boot 3.5, PostgreSQL, Caffeine Cache
- ta4j — RSI/MACD/EMA технические сигналы
- TelegramBots API (long polling)
- XChange — интеграция с Binance/Bybit
- AES-256-GCM — шифрование ключей биржи пользователя в БД
- Spring AI MCP (server) — второй Maven-модуль, свои инструменты для AI-агента

## Структура

```
currency-bot-showcase/
├── src/main/java/com/polybezev/currencybot/   основной бот
│   ├── bot/          CurrencyBot — диспетчер апдейтов
│   ├── handler/       Command/Admin/Payment/Trade
│   ├── service/        AiAnalysisService, TradeService, ExchangeService, ...
│   ├── scheduler/       дайджест/сигналы/автоторговля по расписанию
│   ├── util/NavigationUtil.java   централизованная отмена FSM-ввода
│   └── controller/InternalPortfolioController.java   read-only для mcp-server
├── mcp-server/                                  отдельный Spring Boot процесс
│   └── src/.../service/  RssNewsService, MarketDataService, PortfolioService
├── docker-compose.yml     PostgreSQL одной командой
└── .env.example (в обоих модулях)   шаблон переменных окружения без секретов
```

## Быстрый старт

```bash
cp .env.example .env                    # заполнить реальными значениями
cp mcp-server/.env.example mcp-server/.env

docker compose up -d                    # PostgreSQL

mvn spring-boot:run                     # бот, порт 8080
cd mcp-server && mvn spring-boot:run    # mcp-server, порт 8081
```

`INTERNAL_MCP_TOKEN` должен совпадать в `.env` бота и `mcp-server/.env` —
это общий секрет для внутреннего эндпоинта портфеля.

Юнит-тесты (не требуют БД/токенов):

```bash
mvn test
```
